# Hospital Operations Data Quality Log

This log records every material data-quality issue found in the hospital operations dataset, the evidence behind it and the decision taken. The raw table is never changed. Fixes and flags are applied only when the clean table is built.

**Re-verification:** every finding below was reproduced against `hospital_operations_raw` on 29 October 2026 using [`02_raw_data_profiling.sql`](../sql/02_raw_data_profiling.sql), except where marked as historical. Figures are raw counts across all 5,075 rows. Fixes and flags were then applied in [`03_data_cleaning.sql`](../sql/03_data_cleaning.sql) and confirmed against `hospital_operations_clean` on 31 October 2026 using [`04_cleaning_validation.sql`](../sql/04_cleaning_validation.sql). Figures quoted from the clean table are counts across its 5,000 rows.

## How to read each row

- **Issue ID:** a fixed reference (DQ-001 onwards) used in scripts and commit messages. IDs are never reused or renumbered.
- **Stage:** the point in the pipeline where the issue was found.
- **Field(s) affected:** the column or columns involved.
- **Finding:** what is wrong, in plain terms.
- **Evidence:** the figures that prove it.
- **Impact:** why it matters for the analysis, with the business questions affected.
- **Action / Decision:** whether the issue is fixed, flagged or left, and how.
- **Where it's handled:** the script and section that check the issue, and the scripts that deal with it and confirm it.
- **Status:**
  - **Fix agreed / Flag agreed:** decided at profiling, not yet applied and validated.
  - **Resolved:** fixed in the clean table and confirmed by validation.
  - **Flagged:** kept as recorded, marked in the clean table and confirmed by validation.
  - **Accepted:** left as recorded, for the reason given.
